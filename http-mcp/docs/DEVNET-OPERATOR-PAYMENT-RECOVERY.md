# Original issued native-payment recovery

The operator durably records the exact unsigned native-payment intent before the packaged wallet starts its one approved send. The private run binds the payer, payee, amount, nonce, native data, payload digest, Agreement/job, admitted network/chain and transport binding. Its public receipt exposes only those public facts and hashes; it contains no handoff token, OAuth material, mnemonic or private key.

If the packaged wallet's local result is lost before the buyer driver stores the transaction hash, resume does not call `sendTransaction`, prepare another payment, request another transaction approval or guess the latest wallet lane. It requires exactly one matching approved native-payment evidence record and exactly one immutable `devnet/native-transfer/<hash>` record whose retained content hash and Ed25519 payer signature match the original intent. It then performs the transport's existing current readback for that exact payer and hash. Only an included readback with the same nonce, parties, amount, network and chain identity is saved as the recovered payment and reported through the original private operation capability.

An absent or non-unique original record, missing or non-unique approval evidence, pending/rejected/different readback, or unavailable source remains held with `noResend: true`. A normal decline stays declined. Reading an older completed run never uses the newer wallet lane; recovery scans the immutable per-hash records and leaves unrelated run receipts unchanged.

The `testOnlyAfterNativeWalletResult` callback exists only on the loopback operator's buyer-driver construction API so the owned acceptance test can end the local response after the real packaged-wallet send has returned but before the driver records its hash. The original payment-recovery test throws from that callback and recreates app/operator/seller services in the same Node process; it is not a process-crash or dropped-wallet-HTTP-response proof. A separate CLI-issued-recovery test owns the distinct-process `SIGKILL` boundary. The callback receives public identifiers only. It is not configured by operator JSON and supplies no payment, approval, readback or authority.

This is source-owned normalized Node2 loopback evidence. It does not establish public Node2 execution, consensus finality, production trust, security review or full DACS v0.1 acceptance.
