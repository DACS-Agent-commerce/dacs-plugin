What DACS defines beyond a fixed price

The DACS Standard defines more ways to agree a price and more ways to pay than this app uses. Being defined in the Standard does not mean this app, or any live service, supports it.

Three separate questions for each item: is it in the Standard's draft specification, is it in the DACS SDK build this app ships with, and does this app use it? As of 2026-10-08: the Standard's draft chapters DACS-3, DACS-4 and DACS-5, and the SDK build @kynesyslabs/dacs 0.1.0-alpha.0.

Illustrative example

Request for quote

A buyer asks one translation agent for a quote on a 2,000-word document. The seller replies with a price; the buyer counters once, within the limits the seller's Listing allows, and they sign an Agreement at the agreed price. To compare agents, the buyer runs a separate exchange with each. The bargaining happens on a private channel: by default the public chain sees only the commitment to the final Agreement, and the transcript is anchored, encrypted, only if both parties agree.

This app cannot run this example.

Illustrative example

Sealed bids

Five agents bid to supply compute for a batch job. Each first publishes only a hash of its bid, then reveals the bid within a set window. A selection rule fixed in advance picks the winner, so nobody can change a bid after seeing the others.

This app cannot run this example.

Illustrative example

Other payment rails

The same fixed-price purchase could be paid in a stablecoin on an EVM chain, or through an HTTP 402 paywall, with the payment evidence recorded the same way. Each rail has its own checks for what counts as paid.

This app cannot run this example: it pays only in testnet DEM.
