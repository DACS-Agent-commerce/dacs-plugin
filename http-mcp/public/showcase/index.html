See how an agent buys a service with DACS

DACS is an open standard for agent commerce in five stages: Identify, Vet, Negotiate, Settle and Verify. This app can run one of its purchase types, a fixed-price report paid in DEM on the Demos testnet, on servers whose operator has set up live purchases. You have two ways to see it.

1. Walk through a purchase (read-only)

Follow one fixed-price purchase stage by stage, with an illustrative receipt.

  • No sign-in, wallet or testnet DEM needed.
  • Illustrative only: it cannot buy anything, and its examples are not real transactions.

Start the walkthrough

2. Make a live testnet purchase

Where this server offers live purchases, start the seller's demonstration purchase in ChatGPT, with real Demos testnet transactions. The shipped composition stops before payment while independent commitment finality is unavailable.

  • Not every server offers this. Ask ChatGPT to start the DACS showcase: it tells you whether this server has the live purchase setup, but not whether your account may buy.
  • Start it in ChatGPT with the DACS app, not on this page. This page cannot start a purchase.
  • You need to sign in to the DACS app, set up a wallet in its portal, and hold enough testnet DEM for the price and transaction fees.
  • You approve each buyer-side signature and transaction in your wallet. Testnet DEM only; never mainnet.
  • The operator decides which accounts may buy and may admit only its own test accounts. A purchase can also wait for the seller's approval.

What "verified" means here

The app checks what one Demos testnet node reports: that a signed record exists and matches, or that a payment was included. That is not a finality proof or an independent audit, and it says nothing about the seller's business identity or the quality of the service. The shipped live testnet flow holds before payment because independent finality of the seller commitment is not established. Earlier Agreement and seller records can already be on the testnet. Verify is also pending: a composition that later passes the finality gate can show a report with the completion audit pending in this profile.
